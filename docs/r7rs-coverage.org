#+TITLE: R7RS-small coverage
#+DESCRIPTION: What iota implements of the R7RS-small report, row by row, with the tests behind each row, the results of an outside test suite, the deliberate deviations and the known defects.
#+SETUPFILE: setup.org
#+OPTIONS: num:nil

What iota covers of the [[https://small.r7rs.org/][R7RS-small]] report, chapter by chapter, and
what backs each row.

The Status column is =yes=, =part= with a note, or =no=. The Tests
column names the tests that exercise the row:

- =Reader=, =Number=, =Printer=, =Macro=, =Property=, =Eval=, =Scheme=,
  =Ports= and =Coverage= are the modules =test/Test/NAME.hs=. What
  follows the colon is a test group of that module, as in =Eval: tail
  calls=, or the name of one test where the module has no groups. A
  module name on its own means all of it. =Coverage= holds the cases
  that were written for rows of this page which nothing else tested.
- =golden: NAME= is the program =test/scheme/NAME.iota=, whose output
  is compared with =test/golden/NAME.golden=.
- =Examples: NAME= is the program =examples/NAME.iota=, whose output is
  compared with =test/golden/examples/NAME.golden=.

=make test= runs them all, see [[file:hacking.org::#tests][Tests]]. It also runs the examples
in this documentation. Those are not counted on this page.

To run one group, give its name to the test program, as in
=cabal test --test-options='-p "tail calls"'=. Inside the test program
the tests of a module are a group named after the module, with four
exceptions: =Scheme= is the group "Scheme programs", =Macro= is
"syntax-rules", =Property= is "properties" and =Ports= is "files and
processes". The golden programs are the group "Golden".

A test is listed for a row only if it would fail were the feature
broken. Where part of a row has no such test the column says which
part, with the word =none=. Every status and note was also checked by
hand against the interpreter when this page was last revised, so a
part marked =none= worked then, but no test keeps it working.

That is all the tables claim. A test covers the cases it tries, not
the report. In chapter 6 a row is a whole section of the report. Every
procedure of the section is called by some test, but for many of them
that is one simple call, see [[#procedures-that-no-test-calls][after the table]].

After the tables come the results of an [[#conformance-suite][outside test suite]], the
places where iota [[#deviations-and-extensions][deviates from the report on purpose]], and the
[[#known-defects][known defects]]. A note in a table such as "Known defects 4" refers to
an item of that last list. A row with such a note has the status
=part= when the report requires what is missing, and keeps =yes= when
the defect is in something the report leaves to the implementation.

** Procedures that no test calls
   :PROPERTIES:
   :CUSTOM_ID: procedures-that-no-test-calls
   :END:

   None. Each of the 339 names the standard libraries export is used
   by at least one test in =test/Test=, =test/scheme= or =examples=,
   directly or through the standard library.

   For about a third of them that test is in =Coverage=, which was
   written to close this gap: the accessors of =(scheme cxr)=, most of
   the character and string comparisons, the trigonometric procedures,
   =gcd= and =lcm=, the port predicates, the procedures of
   =(scheme file)= and others. =Coverage= gives each of them one or
   two simple calls. That shows the procedure is there and gets the
   plain case right. It says little about the corners.

** Deviations the suite found
   :PROPERTIES:
   :CUSTOM_ID: deviations-the-suite-found
   :END:

   Five defects. Each is a place where the report requires one thing
   and iota does another. In the list of [[#known-defects][Known defects]] they are items
   4, 6, 7, 10 and 5, in the order given here.

   1. The reader rejects a radix prefix inside a bytevector literal.
      =#u8(#x41 #x42)= is a read error, although section 7.1.1 allows
      any exact integer from 0 to 255 there. The suite writes eight
      tests of =utf8->string= and =string->utf8= this way. Since iota
      reads a whole file before running it, the harness rewrites those
      bytes in decimal, and the eight tests then pass.
   2. Pattern variables inside an escaped template are not substituted.
      Section 4.3.2 says that =(... template)= is the template with its
      ellipses treated as ordinary identifiers. iota copies the whole
      template literally, pattern variables included. Two tests.
   3. An ellipsis that is also in the literals list is still treated as
      the ellipsis. Section 4.3.2 says it is then matched as a literal.
      The suite's one test of this is rejected when the form is
      expanded, so the harness removes it and counts it as a failure.
   4. =map= and =for-each= reject a circular list. Section 6.10 allows
      circular lists as long as one list is finite. Two tests.
   5. The sign of an infinite imaginary part is lost when a number is
      read, so =+inf.0-inf.0i= reads as =+inf.0+inf.0i=. Four tests,
      two that compare the value and two that write it back.

   What iota answers today:

   #+begin_example
     iota> (guard (e ((read-error? e) 'read-error)) (read (open-input-string "#u8(#x41 #x42)")))
     read-error
     iota> (define-syntax esc (syntax-rules () ((_ x) '(... (x ...)))))
     iota> (esc 100)
     (x ...)
     iota> (define-syntax lit (syntax-rules ... (...) ((_ x ...) 'literal) ((_ . rest) 'other)))
     iota> (lit 1 2 3)
     literal
     iota> (define circle (list 1 2))
     iota> (set-cdr! (cdr circle) circle)
     iota> (guard (e (#t 'error)) (map + circle '(10 20 30)))
     error
     iota> (imag-part (string->number "1.0-inf.0i"))
     +inf.0
   #+end_example

   The report wants =#u8(65 66)=, =(100 ...)=, =other=, =(11 22 31)=
   and =-inf.0= in that order.

** Failures that are not deviations
   :PROPERTIES:
   :CUSTOM_ID: failures-that-are-not-deviations
   :END:

   The other 19 failing tests expect something R7RS-small does not
   require.

   - Ten tests read numbers with the exponent markers =s=, =f=, =d= and
     =l=, as in =1s2=. The grammar of section 7.1.1 has only =e=, and
     the report's notes say the other four are no longer required. iota
     reads =1s2= as a symbol.
   - Three tests expect =read= to raise an error on a malformed datum
     comment such as =(a #;. b)=. The report only requires an error for
     input that ends inside a datum. iota reads a lone =.= as the symbol
     =|.|=, which the grammar does not allow, so the comment swallows
     the dot and the result is =(a b)=.
   - One test expects =(apply +)= to raise an error. The report does
     not require that error to be signalled. iota returns 0.
   - Two tests accept only =e+308= in the output of =number->string=.
     iota writes =1.7976931348623157e308=, which reads back as the same
     number.
   - One test expects =write= to put bars around the symbol
     =+NaN.0abc=. iota writes it without bars, and it reads back as the
     same symbol.
   - One test expects =(file-exists? ".")= to be =#t=. The report does
     not say whether a directory is a file. iota answers =#f= for a
     directory.
   - One test expects =(string->number "#x4000000000000001/3e1")= to be
     =#f=. Under the grammar of section 7.1.1 this is a hexadecimal
     rational, since =e= is a hexadecimal digit, and iota returns
     4611686018427387905/993.

* Deviations and extensions
  :PROPERTIES:
  :CUSTOM_ID: deviations-and-extensions
  :END:

  The deliberate ones: where iota goes beyond the report, or picks one
  of the choices it leaves open. The places where iota does not do
  what the report requires are under [[#known-defects][Known defects]]. Each item ends
  with its tests, named as in the tables.

  1. A complex number is exact only when both parts are. Mixing an
     exact and an inexact part makes both inexact, so =1+2.0i= is
     =1.0+2.0i=. A real number with an inexact zero imaginary part stays
     complex, as in the report, so =(real? 1.0+0.0i)= is =#f=. Tests:
     Number; Eval: complex numbers.
  2. The repl and scripts start with every standard library and
     =(iota extras)= imported. An explicit =(import ...)= is accepted
     and is what a portable program should write. A =define-library=
     starts empty. Tests: Eval: stdlib; Eval: import and
     define-library; Coverage: program structure.
  3. Extensions:
     - =[= and =]= as parentheses. Tests: Reader: lists.
     - An atom that does not read as a number is an identifier, so =1+=
       and =1-= are identifiers although they start with a digit, and a
       dot on its own, where a datum is expected, is the symbol written
       =|.|=. Tests: Reader: atoms, for =1+=.
     - =named-lambda=, as in MIT Scheme. =(named-lambda (name arg ...)
       body ...)= is a =lambda= whose procedure prints as
       =#<procedure name>=. The name is not bound in the body. Tests:
       Coverage: program structure, but not for the last point.
     - Curried =define=. =(define ((f a) b) ...)= defines =f= as a
       procedure of =a= that returns a procedure of =b=. Tests:
       Coverage: program structure.
     - =(define x)= with no value. =x= is bound, and reading it before
       it has a value is an error. In a body =set!= gives it one. At
       the top level that does not work, see [[#known-defects][Known defects]]. Tests:
       Coverage: program structure, for the body.
     - In =define-record-type=, =#f= in place of the constructor or of
       the predicate defines none, and a constructor written as a bare
       name takes every field in order. Tests: Coverage: program
       structure.
     - =(force x)= returns =x= when =x= is not a promise. Tests: Eval:
       promises and parameters.
     - =eval= with one argument uses the interaction environment.
       Tests: Eval: eval.
     - A program may define a name it has imported, and the definition
       replaces the import in that program. Assigning an imported name
       with =set!= is a syntax error. Tests: Coverage: program
       structure; Coverage: expressions.
     - =(scheme r5rs)= also exports =unquote= and =unquote-splicing=.
       Tests: none.
     - The =(iota extras)= library, described on
       [[file:procedures.org::#iota-extras][Libraries and procedures]]. Tests: Eval: stdlib.
  4. =(eqv? (vector) (vector))= is =#f=, since they are fresh objects.
     The same goes for two empty strings or bytevectors. The report
     leaves it unspecified. Tests: Eval: strings and chars; Coverage:
     equivalence.
  5. A continuation captured inside a =define-library= body and invoked
     after the library has been loaded runs the rest of that body and
     then stops. The program that invoked it does not go on: its
     remaining forms never run, and nothing is reported. Inside a
     program a continuation can be re-entered across top level forms,
     and in the repl across inputs. Tests: Eval: re-entrant
     continuations and dynamic-wind, for top level forms. The library
     case: none.
  6. Literal constants are immutable. That covers quoted data, string,
     vector and bytevector literals, a quasiquoted form with nothing
     unquoted in it, and the result of =symbol->string=. The mutators
     signal an error instead of silently changing program text. Tests:
     Eval: strings and chars; Coverage: literal constants.
  7. A definition after an expression in a body is a syntax error. The
     top level is not affected. Tests: Eval: strings and chars.
  8. =(features)= and =cond-expand= do not list =exact-complex=,
     although complex numbers with exact parts are supported. Tests:
     Eval: cond-expand and features, for the list as it is.
  9. =(exit obj)= takes =#t=, =#f= or an integer. Any other object is
     an error, not an exit. An integer other than 0 becomes a status
     from 1 to 255. Tests: Ports: exit unwinds dynamic-wind and
     reports its code, for one integer; Coverage: system interface, for
     =#t=, =#f= and no argument.
  10. Some things the report calls an error without requiring a signal
      are not signalled. A numeric predicate such as =zero?= or
      =exact?= answers =#f= for an object that is not a number,
      =(apply +)= is 0, and =utf8->string= decodes invalid bytes as
      the replacement character U+FFFD. Tests: none, on purpose. These
      are not answers to hold in place.

* Known defects
  :PROPERTIES:
  :CUSTOM_ID: known-defects
  :END:

  The places known so far where iota does not do what the report
  requires. It is not a complete list: each review of this page has
  added to it. Items 4, 5, 6, 7 and 10 were found by the
  conformance suite and are described under [[#deviations-the-suite-found][Deviations the suite found]],
  and =test/conformance/run.sh= notices when one of them is fixed. The
  others were found by reading the report against the interpreter. No
  test in the repository covers them, since a test would have to
  expect the wrong answer.

  1. A dotted tail that is itself a list is not taken as that list
     when the datum is code. =(+ . (1 2))= is the same datum as
     =(+ 1 2)=, but iota answers =bad syntax in expression (improper
     list)=. The usual way to meet this is a =syntax-rules= template
     with a dotted tail: =(f . args)= or =(lambda formals . body)=
     expands into such a form and fails the same way. Writing the
     pattern and the template with an ellipsis, =(f arg ...)=, avoids
     it. In the same way =(1 unquote x)= inside a quasiquote is not
     taken as =(1 . ,x)=. As data, a list written like this is read
     correctly.
  2. The reader fails on a label that is used again after a labelled
     datum which refers to itself. Reading ~(#0=(1 . #0#) #0#)~ does
     not return, from a port or as a quoted literal in a program, and
     ~#0=(a #1=(b #0#) #1#)~ ends with =stack overflow=. The first is
     what =write= prints for a list that holds the same circular list
     twice, so iota cannot read back everything it writes.
  3. =#!fold-case= and =#!no-fold-case= hold for the rest of the datum
     being read, not for the rest of the port. With a port on the text
     =#!fold-case ABC DEF=, the first =read= returns =abc= and the
     second =DEF=. A source file is read in one go, so there a
     directive lasts to the end of the file.
  4. A radix prefix inside a bytevector literal, as in =#u8(#x41)=, is
     a read error.
  5. The sign of an infinite imaginary part is lost when a number is
     read, by the reader and by =string->number=: =1.0-inf.0i= reads as
     =1.0+inf.0i=.
  6. =syntax-rules= does not substitute pattern variables inside an
     escaped template, =(... template)=.
  7. An ellipsis that =syntax-rules= is given among its literals is
     still treated as the ellipsis.
  8. =number->string= signals an error for an inexact number when the
     radix is not 10. The report asks for a string that
     =string->number= reads back in that radix, and there is one:
     =#i1/10= in radix 2 for 0.5.
  9. Three things in the handling of Unicode. =char-alphabetic?=,
     =char-upper-case?= and =char-lower-case?= go by the general
     category of a character, where the report names the properties
     Alphabetic, Uppercase and Lowercase. They are wrong for U+2160, a
     Roman numeral that is alphabetic and upper case, for U+24D0, a
     circled letter that is lower case, and for U+01C5, a title case
     letter that is not upper case. =char-foldcase=, and with it the
     =char-ci= comparisons, folds both U+0130 and U+0131 to =i=, which
     the simple case folding does not. =string-downcase= writes σ for
     a sigma at the end of a word, where the full lower-casing writes
     ς.
  10. =map= and =for-each= reject a circular list.
  11. =null-environment= returns the same environment as
      =scheme-report-environment=, with the procedures of
      =(scheme r5rs)= as well as its syntax, where the report wants
      the syntactic keywords only. =(eval 'car (null-environment 5))=
      returns the procedure. Both procedures accept any version
      argument, or none.
  12. =input-port?= and =output-port?= answer =#f= for a port that has
      been closed. In the report they say what kind of port an object
      is, and =input-port-open?= and =output-port-open?= say whether
      it is open. =textual-port?= and =binary-port?= are not affected.
  13. =get-output-string= and =get-output-bytevector= signal an error
      once their port has been closed. What a string port collected
      can therefore not be fetched after =call-with-port= has closed
      it.
  14. =write= prints the two-element list =(unquote @a)= as =,@a=,
      which reads back as =(unquote-splicing a)=.

  The rest are defects in what iota adds to the report, or in things
  the report leaves to the implementation:

  15. [@15] After =(define x)= at the top level, =(set! x 1)= fails
      with =unbound variable: x=. Only another =define= gives =x= a
      value.
  16. =eval= of a datum that is circular through a =car= or through a
      vector element does not return. The interpreter runs out of
      stack and exits with =stack overflow=. A list that is circular
      through its =cdr= is reported as an error.
  17. An uncaught error in a script is reported with the file, line
      and column of the top level form it happened in. That prefix is
      missing when the error happens inside a file reached through
      =load= or =import=, and for the rest of a top level form once
      that form has called =load= or imported a library from a file.
  18. An =include= inside an included file is looked up from the
      directory of the outer file, the program or library being
      processed, not from the directory of the file it is written in.
  19. What a program writes to a file port is lost if the port is
      still open when the program ends, with or without =exit=. Only
      the standard output and the standard error are flushed. Closing
      the port, or =flush-output-port=, writes the text out.
  20. Bytes that are not valid UTF-8, read from a textual file port or
      from the standard input, end the program. The failure is not a
      Scheme error, so =guard= and =with-exception-handler= do not see
      it.
  21. =error= with a first argument that is not a string, as in
      =(error 'my-proc "msg" 42)=, raises =expected a string= in place
      of the caller's error, and the message and the irritants are
      lost. The report says the message should be a string.
  22. =min= and =max= with a NaN depend on the order of their
      arguments: =(min 0.0 +nan.0)= is =0.0= and =(min +nan.0 0.0)= is
      =+nan.0=.
