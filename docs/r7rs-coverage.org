* Deviations and extensions
  :PROPERTIES:
  :CUSTOM_ID: deviations-and-extensions
  :END:

  1. A complex number is exact only when both parts are. Mixing an
     exact and an inexact part makes both inexact, so =1+2.0i= is
     =1.0+2.0i=. A real number with an inexact zero imaginary part stays
     complex, as in the report, so =(real? 1.0+0.0i)= is =#f=.
  2. The repl and scripts start with every standard library imported.
     An explicit =(import ...)= is accepted and is what a portable
     program should write. A =define-library= starts empty.
  3. Extensions: =[= and =]= as parentheses, =named-lambda=, curried
     =define=, =(define x)=, =(force x)= returning =x= when =x= is not a
     promise, one-argument =eval= in the interaction environment, and the
     =(iota extras)= library.
  4. =(eqv? (vector) (vector))= is =#f=, since they are fresh objects.
     The report leaves it unspecified.
  5. A continuation captured inside a =define-library= body, or across
     top level forms of a program, and invoked after that body has
     finished re-enters a computation nobody is waiting for. The report
     leaves this to the implementation and I have not needed anything
     better.
  6. Literal constants are immutable. That covers quoted data, string,
     vector and bytevector literals, and the result of =symbol->string=.
     The mutators raise an error instead of silently changing program
     text.
  7. A definition after an expression in a body is a syntax error. The
     top level is not affected.
