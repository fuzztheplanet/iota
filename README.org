#+TITLE: iota

[[file:LICENSE][https://img.shields.io/badge/license-MIT-blue.svg]]
[[https://small.r7rs.org/][https://img.shields.io/badge/scheme-R7RS--small-green.svg]]

An R7RS-small Scheme interpreter written in Haskell.

* About

/iota/ implements the whole of [[https://small.r7rs.org/][R7RS-small]], as far as the test suite and the
examples in the report can tell. That includes the things small Schemes
usually skip: exact rationals and complex numbers, hygienic =syntax-rules=,
re-entrant continuations with a correct =dynamic-wind=, the full exception
system and real libraries. It is a single self contained binary with a
readline style repl.

I started iota on my own, years ago, working through the two /Write Yourself a
Scheme/ tutorials by hand. That version was a learning exercise and never got
close to the report. With the rise of AI I picked the name back up and rebuilt
it vibe-coded, to see what the result would look like. So, to be clear: this
project has been mostly (read: entirely) vibe-coded. I said what I wanted, a
language model wrote the code, and I read it, ran it and sent it back until the
tests and the report were happy. The decisions about how it should work are
mine. Most of the typing is not. It does everything I have asked of it so far,
but I would not put it anywhere important.

* Status

Version 0.1. The language is complete with respect to the report and the
interface is not going to change, but the number is low because nobody has
run anything large on it yet. Bug reports with a small program attached are
the most useful thing you can send.

Known limitations:

  - Performance is that of a straightforward CPS interpreter. Fine for
    scripts and for learning, not for number crunching.
  - No foreign function interface and no threads.
  - Error messages give the top level form an error occurred in, not the
    exact expression.

* Building

You need GHC 9.4 or newer and cabal 3.4 or newer. GHC 9.4, 9.6 and 9.8 are
known to work. On Arch that is =pacman -S ghc cabal-install=. Elsewhere,
[[https://www.haskell.org/ghcup/][ghcup]] works.

#+begin_src sh
git clone https://github.com/fuzztheplanet/iota.git
cd iota
cabal build
cabal test
cabal install         # puts an iota binary on cabal's install path, usually ~/.cabal/bin
#+end_src

The executable is self contained. The Scheme half of the standard library is
compiled into it, so you can copy the binary anywhere and forget about the
source tree.

* Usage

#+begin_src sh
iota                     # start the repl
iota FILE.iota [ARG...]  # run a script. ARGs are visible in (command-line)
iota run FILE.iota       # the same, spelled out
iota eval '(+ 1 2)'      # evaluate one expression and print it
iota --version
#+end_src

A session looks like this:

#+begin_example
    $ iota
    iota, an R7RS-small Scheme. Type :help for help.
    iota> (define (fact n) (if (= n 0) 1 (* n (fact (- n 1)))))
    iota> (fact 30)
    265252859812191058636308480000000
    iota> (sqrt -4)
    +2i
    iota> (call/cc (lambda (k) (+ 1 (k 42))))
    42
#+end_example

The repl completes bound names on tab, keeps its history under
=~/.local/state/iota/=, continues an unbalanced line on the next one and has a
few =:= commands. =:help= lists them. Scripts and the repl start with every
standard library imported, so you can type =(display "hi")= without an
=import= first. A portable program should still say =(import (scheme base))=
at the top.

Source files end in =.iota=, scripts and libraries alike. =(import (my lib))=
looks for =my/lib.iota= next to the importing file and then in the directories
listed in =IOTA_LIBRARY_PATH=. A library file holds nothing but
=define-library= forms. That is what makes it a library, not the name.

The =examples/= directory has a few small programs. =iota examples/fib.iota=
runs one of them.

* Coverage

Everything in R7RS-small. In more detail:

- The whole datum syntax, including datum labels, =#;= comments, nested block
  comments and =#!fold-case=.
- Exact integers and rationals of any size, IEEE doubles, complex numbers in
  rectangular and polar notation, and the contagion rules between them.
  Inexact numbers print as =0.01= rather than =1.0e-2=.
- Mutable pairs, strings and vectors. Literal constants are immutable.
  =equal?= terminates on cyclic data.
- Proper tail calls. =call/cc= continuations can be re-entered, and
  =dynamic-wind= runs its before and after thunks on every entry and exit.
- Hygienic =syntax-rules=, with nested ellipsis, a custom ellipsis identifier,
  =(... ...)= and =_=. Also =let-syntax=, =letrec-syntax= and =syntax-error=.
- The exception system from chapter 6.11, with =with-exception-handler=,
  =raise=, =raise-continuable=, =guard= and error objects.
- =define-library= and =import= with =only=, =except=, =prefix= and =rename=.
  Every =(scheme ...)= library of the report is there.
- Records, parameters, promises, =case-lambda=, multiple values, string ports,
  bytevector ports, file ports, =eval=, =load=, =exit= and the time
  procedures.

The few places where iota goes beyond the report or picks one of the choices
it leaves open are listed at the end of [[file:docs/r7rs-coverage.org][docs/r7rs-coverage.org]], next to the
full table.

The report itself is at [[https://small.r7rs.org/][small.r7rs.org]] and the PDF is
[[https://small.r7rs.org/attachment/r7rs.pdf][r7rs.pdf]]. Chapter 4 covers the syntax, chapter 6 the procedures and chapter 7
the formal grammar and the reference implementations of the derived forms.

* Contributing

Bug reports and patches are welcome. Run =cabal test= before sending a change,
keep =-Wall= clean, and add a test for whatever you fixed. A golden test is
one file under =test/scheme/=. [[file:docs/hacking.org][docs/hacking.org]] has the rest.
